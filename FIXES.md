# What this mod fixes

Player-facing list of every fix and change, used for the Workshop page and change notes.
One line per fix: what was wrong → what the mod does. Newest first inside each section.
Mark entries not yet released as (unreleased).

## Multiplayer: desyncs

- Crew working a job of another ship (moving resources between your own ships, helping build another ship) could change that job from two threads at once in multiplayer, so its progress or crew list could differ between clients. When such a crew arrives or gives up on a path while on its own ship, the step is now queued and applied right after the parallel ship update, the same way the game already handles crew on other ships. All players need this mod. (unreleased)
- Station delivery missions could go out of sync in multiplayer: when two ships traded with the same station at the same moment, the game updated the station's offered delivery mission progress from two threads at once, so an update could be lost or applied in a different order on some clients. These updates are now queued and applied right after the parallel ship update, in the game's fixed ship order. All players need this mod. (unreleased)

- Player money could go out of sync in multiplayer: when two ships of the same player traded with stations (or got pre-purchased resources refunded) at the same moment, the game updated the balance from two threads at once and one change could be lost on some clients. Money changes made during the parallel ship update are now collected safely and applied once, in a fixed order, right after it. All players need this mod. (unreleased)

## Multiplayer: diagnostics

- The mod log gets a 10-second network summary (freezes, input arrival margin, ping per player) to help diagnose multiplayer lag. Log only, gameplay is unchanged. (unreleased)

## Performance: stutter and FPS spikes

- When a ship broke apart, the game cleaned up the copied part settings (toggles, crew and resource links, weapon settings) of every new piece by building a throwaway list of the removed entries each time (about 20 MB of garbage in a 40-ship battle, adding to memory clean-up stutter). The same entries are now removed in the same order using one reused list. Set `UNOFFICIAL_PATCH_SPLIT_ALLOC=0` to turn it off. (unreleased)
- A looping sound shared by many weapons or parts kept every user in the real sound's stop listener list, and each user that stopped rebuilt that whole list (about 26 MB of garbage in a 40-ship battle). Users are now kept in a list that adds and removes them directly, and they are still notified in the same order when the sound stops. Set `UNOFFICIAL_PATCH_SOUND_STOP_HUB=0` to turn it off. (unreleased)
- The game's helper threads for parallel work never rest while a game is running: between jobs each of them keeps polling for new work, which in a 40-ship battle burns about two thirds of the game's CPU time on doing nothing and takes processor time and boost headroom from the threads doing real work. Idle helper threads now sleep after a short wait and are woken the moment new work is published (and at least every 10 ms), so CPU use drops by about 60% and the simulation runs a few percent faster. Work order and simulation results are unchanged. Set `UNOFFICIAL_PATCH_IDLE_PARK=0` to turn it off. (unreleased)
- Single player at 2x-8x speed: when the computer cannot run the simulation that fast, the game crammed up to eight simulation ticks into each frame, so a big battle fell from ~26 fps at 1x to ~7 fps at 8x. Now each frame runs only as many ticks as fit the time left in a frame after drawing (measured tick cost, at least two thirds of a frame) and never fewer than 1x would; the game time that does not fit is dropped, so the game runs below the selected speed instead of the frame rate collapsing. Where the computer keeps up, nothing changes. Multiplayer is not affected. Turn off with `UNOFFICIAL_PATCH_TICK_BUDGET=0`. (unreleased)
- After every physics step the game looks for the earliest collision of fast objects (bullets, and ships, which the game also treats as fast objects): for every bullet impact it walked the whole list of touching objects again and re-checked each one, the largest single cost of a battle tick (about a fifth of the main thread with 40 ships). Those checks only read the world, so they now run on all CPU cores at the start of each pass; the pass itself then runs exactly as before, in the same order. After the first pass only the contacts whose result can have changed are checked again (those of the objects the pass moved, solved or that a hit changed, and new ones: about 300 of 4,900 per pass), so idle worker threads are no longer woken for every pass. Collision results are bit-identical. Set `UNOFFICIAL_PATCH_TOI_SCAN=0` to turn it all off, or `UNOFFICIAL_PATCH_TOI_INCREMENTAL=0` to check every contact on every pass again. (unreleased)
- Each destroyed part made the game walk outward through the rest of the ship to refresh queued construction and deconstruction work, even on ships with nothing queued (about 1 ms of every combat tick with 40 ships). That walk is now skipped when the ship has no queued construction or deconstruction; ships with queued work behave exactly as before. Set `UNOFFICIAL_PATCH_CONSTRUCTION_FLOOD_SKIP=0` to turn it off. (unreleased)
- Every armor and hull part of a ship listens for the ship's physics body being replaced; each time one of these thousands of parts was destroyed, the game rebuilt the ship's whole listener list, creating garbage that adds to memory clean-up stutter in battles. Listeners are now kept in a list that adds and removes them directly and calls them in the same order as before. Set `UNOFFICIAL_PATCH_DESTROYING_BODY_SUBSCRIBERS=0` to turn it off. (unreleased)
- Every engine glow, thruster flame and similar part effect listens for camera zoom changes; each time one of thousands of such parts was destroyed or switched off, the game rebuilt the whole listener list, creating garbage that adds to memory clean-up stutter in big battles. Listeners are now kept in a list that adds and removes them directly, and they are still called in the same order. Set `UNOFFICIAL_PATCH_ZOOM_SUBSCRIBERS=0` to turn it off. (unreleased)
- Whenever a sound, effect, beam or crew member stopped or started, the game searched for it in a list of thousands of active objects by comparing them one by one (about a tenth of the main thread in a 40-ship battle). The same entry is now found by a much faster identity comparison and removed the same way, so the order of updates is unchanged. Set `UNOFFICIAL_PATCH_SCENE_BUCKET_REMOVE=0` to turn it off. (unreleased)
- Optional, single player: every frame slower than the game's frame target (a garbage collection pause, a heavy batch of combat ticks) loses game time for good: the game gives the simulation less time than has passed and drops the rest, so a big battle at 8x speed runs about 3% slower than 8x. With `UNOFFICIAL_PATCH_SP_CATCHUP=1` the dropped time is kept (up to one second) and handed to the next frames, but no frame ever runs more simulation ticks than the game itself allows per frame; in that battle the game then holds the full 8x. Simulation results per tick are unchanged; multiplayer is not affected. The cost is frame rate: the extra ticks have to run somewhere, so fps drops a little at 8x and a lot in a battle the computer cannot keep up with even at 1x (there the game runs faster than without it but can still fall below normal speed). Off by default. (unreleased)
- Whenever a ship gains or loses a part (in combat: every destroyed part), its outline is recalculated, and for every corner of every part the game looked up each neighbouring part and recalculated that part's rectangle again, a large share of slow combat ticks. The neighbour lookup now skips that redundant rectangle check where finding the part already proves the cell is covered. Ship outlines, bounding circles and collisions are unchanged. Set `UNOFFICIAL_PATCH_BOUNDING_POINTS=0` to turn it off. (unreleased)
- When a part inside a ship was destroyed, the game still threw the ship's outline away and recalculated it from every part, although a part that touches no outline corner and lies inside the outline cannot change it (about a third of the outline rebuilds in a 40-ship battle). After such a removal the outline is now kept as it is; any other change (a part added, a part on the edge removed, the last part) still recalculates it as before. Ship outlines, bounding circles and their update timing are unchanged. The check that ship coordinates stay in a safe range no longer rescans every part after each such removal (a removal cannot move a ship's edge outward). Set `UNOFFICIAL_PATCH_HULL_REMOVAL_SKIP=0` to turn it off. (unreleased)
- When a ship broke apart in combat, the game looked up every decal of the old ship in the decal rules by comparing decal names letter by letter (about half a millisecond per combat tick in a 40-ship battle). That lookup now uses a ready-made table of the same rules, rebuilt whenever the rules change. Which decals are copied, their sizes and their order are unchanged. Set `UNOFFICIAL_PATCH_DECAL_LOOKUP=0` to turn it off. (unreleased)
- Every simulation tick, every ship status that changes its value over time (fire and similar effects on tiles and parts) took two temporary collections to recalculate the values and never gave them back, so both became garbage every tick in combat. They are now given back once the update has finished, also if it fails. Status values and their order are unchanged. The fix now also stays active after the game recompiles that code while running; earlier builds lost it for ship-part statuses shortly after a fight started. Set `UNOFFICIAL_PATCH_STATUS_TEMP_DISPOSE=0` to turn it off. (unreleased)
- Every simulation tick, every moving ship re-checked which nebulas it is in, even on maps without any nebula, and each check took a temporary list of hull points that was never given back, so it became garbage every time. The list is now given back and sized once, and the check is skipped while the map has no nebula and the ship is in none (it would find nothing and change nothing). Nebula results are unchanged. Set `UNOFFICIAL_PATCH_NEBULA_TEMPLIST=0` to turn it off. (unreleased)
- Heat pipe, heat exchanger and radiator glow colours were recoloured on every tiny change of the network's average heat load, rewriting about 19,000 ship sprites per frame with a moving fleet. A glow now updates only when its colour changes by at least 1/255 or reaches fully off or fully on. This is a small, approved visual approximation: each glow colour channel stays within 1/255 of the exact value (where glows overlap or combine, the final pixels can differ slightly more). Only glows whose every value comes from an audited game value type (network, smoothed, combined, accumulated or fixed values) are affected; glows driven by any other kind of value, such as another mod's own value type, update as before. Set `UNOFFICIAL_PATCH_GLOW_QUANTIZE=0` to turn it off. (unreleased)
- Ship sprites were re-sent to the graphics card in full every frame whenever a single sprite of a ship layer changed, including the unused spare capacity (about 7 ms per frame with 40 ships in view); removing a sprite also forced a full resend. Now only the changed parts of each layer are sent (at most four regions per layer), and the rest stays on the graphics card. Drawing is unchanged. Set `UNOFFICIAL_PATCH_ATLAS_RANGE_UPLOAD=0` to turn it off. (unreleased)
- Every frame, every ship re-checked the blueprint toggle of each blueprint network port, network toggle and stat provider, even when nothing had changed (about a quarter of the main thread in a 40-ship battle). The check now runs only on frames where that ship's toggle settings, blueprint parts or a toggle preview changed, and always for a selected or edited ship; the frames it skips are ones where the check would find nothing to change. When another mod's code writes toggles or toggle rules outside the known game paths, or patches the check itself, the original every-frame check is kept; writes made through reflection or runtime-generated code are not detected. (unreleased)
- Every frame, every ship re-checked each radiator and heat exchanger effect value against its target, although most had already reached it (about a tenth of the main thread with 40 ships). Values that have reached a target from a known game source now rest until that target or the value itself changes, then update exactly as before, in the same order and with the same timing; values from other sources, or while another mod patches this code, keep the original every-frame check. Set `UNOFFICIAL_PATCH_SMOOTHED_ACTIVE_SET=0` to turn it off. (unreleased)
- Blueprint network ports repeatedly went through indirect toggle evaluation every frame. Ordinary UI toggles now use a direct path that still reads live state; other rules and incompatible patches retain the original evaluation. (unreleased)
- Shader constant updates boxed numbers, vectors, colors and matrices while checking whether their values had changed, creating substantial garbage when drawing ships and UI. The comparison now uses the same value equality without allocating; buffer writes and rendering stay unchanged. (unreleased)
- Every visible ship searched for the ship under the cursor while drawing its roof, even when the hide-roof key was released. The key is now checked first, avoiding repeated spatial searches and temporary garbage; roof appearance and held-key behavior are unchanged. (unreleased)
- Particle effects checked against the minimap view created a small garbage object on every check (~60 MB per 20 s in big battles). The check now runs without it; which particles are emitted is unchanged. (unreleased)
- Ship parts with network ports, toggles and stat providers created a new object every frame, which triggered frequent memory clean-ups (garbage collection) that cause stutter. Now created once per part. (unreleased)
- Muted background music layers were decoded on every audio buffer even though nobody hears them, producing ~190 MB of garbage per 20 s. Seeking is now deferred until the layer is actually read; audio output is bit-identical. (unreleased)
- Ship thruster acceleration calculation built and threw away a temporary dictionary on every cache miss. It now skips the throwaway and pre-sizes the kept one; results are bit-identical. (unreleased)
- Galaxy map node labels were rebuilt as new strings every frame. The base label text is now cached per node and refreshed on language or rules change. (unreleased)

## Graphics: incorrect colors

- MultiColor components using RGB Max combined their inputs with a minimum operation, producing negative-infinite RGB values for finite source colors. They now take the maximum of each channel; other blend modes and alpha are unchanged. (unreleased)

## Experimental (off unless you turn it on)

- Ion beams in big battles check what they hit one by one on the main thread, about 4 ms of every combat tick. An opt-in experiment (`UNOFFICIAL_PATCH_BEAM_PARALLEL=1`) runs those hit checks on all cores before the beams fire and uses a result only when every input still matches. Beams that hit crew floating in space are now checked in parallel too, instead of sending the rest of the tick back to normal. Anything unusual (a beam stopping, a bullet shot down, unknown add-on logic) makes the rest of that tick run normally. Off by default. When turned on it now also works in career, PvP and multiplayer games (only game modes whose friend/enemy and invulnerability rules were checked; any other mode runs normally). (unreleased)
- Ion beams in big battles check what they hit one after another on the main thread, and each check sees the world as the earlier beams of the same tick left it, so the work cannot be spread over cores. A second single-player opt-in experiment (`UNOFFICIAL_PATCH_BEAM_FROZEN=1`) changes the rule instead: all beams of one tick see the world as it was at the start of that beam step, their hit checks run on all cores, and the hits are then applied one by one in the game's usual order. A beam whose emitter was stopped or moved earlier in the same step is cancelled for that step, and a target destroyed earlier in the step is not hit again. Combat results can therefore differ from the normal game. Multiplayer always uses the normal path, and it cannot be combined with `UNOFFICIAL_PATCH_BEAM_PARALLEL`. Off by default; about 11% faster combat tick (median) in a 40-ship benchmark. (unreleased)
- Secondary beam raycasts repeatedly validated the same weapon target. A benchmark-only experiment reuses a target within a guarded native query, including supported native secondary filters in Creative mode, and falls back to native calls when state or callbacks are unsupported. Required loader patches are checked explicitly; unverified patches keep the experiment off. Compatibility checks reuse resolved method metadata while checking current hooks, avoiding repeated reflection garbage. Disabled by default; correctness and game performance validation are incomplete. (unreleased)
- Raycast helpers retained their last callback and hit data, could return old payload after a miss, and overwrote temporary results during nested queries. An opt-in experiment clears scratch state on success or failure and preserves active outer helper state. Same-world reentrancy remains unsupported because native traversal stacks are shared. Game memory and performance validation are incomplete. (unreleased)
- Empty wrecks were checked increasingly rarely in large battles. An experimental benchmark-only switch keeps cleanup checks on a fixed cycle while preserving rebuild plans and other native protections. Off by default; game performance validation is incomplete. (unreleased)
- Idle-worker experiment: the game busy-spins while pool threads have no tasks. An opt-in guarded path waits for a work notification after a short spin, preserving native task execution, completion waits and worker priorities. Disabled by default while frame-time and simulation-speed validation are incomplete. (unreleased)
- Server GC: the game uses .NET's workstation garbage collector. Opt-in switch to the server collector (`System.GC.Server` in `Cosmoteer\Bin\Cosmoteer.runtimeconfig.json`, only that key is changed, original backed up once as `.unofficialpatch.bak`). Vanilla bench: frame p99 -18%, GC pause time -71%, frames over 33 ms -74%, but the worst single frame +33% and short spikes (over 2x median) 0.9 → 3.0 per minute, and more RAM. Enable: create an empty file `unofficial-patch-server-gc.txt` in the Cosmoteer folder in Saved Games (next to Saved Ships), start the game once, restart it. Disable: delete that file, start the game once (the mod restores the previous value if the config was not changed since), restart. If you remove the mod first, delete `"System.GC.Server": true` from that config by hand. Steam "Verify integrity of game files" also resets it. (unreleased)
- Every beam's hit checks start on its own ship, so each tick the game tested the beam (ion beams: a 16-tile-wide band) against hundreds of the ship's own parts, which the beam then ignores: about three quarters of all beam hit-check time in a 40-ship battle, all on the main thread. When the game's own rules say the firing ship's parts and shields cannot be hit by that beam, the mod now skips the ship's own parts in those checks. Hits, damage and their order are unchanged; any beam whose own ship could be hit (or an unusual game mode or add-on) is checked as before. Set `UNOFFICIAL_PATCH_BEAM_OWN_SKIP=0` to turn it off. (unreleased)
